# State and History

State and History는 OntoFlow가 추적 가능한 업무 자동화를 만들기 위해 가장 중요하게 보는 영역입니다.

## 1. 왜 필요한가

업무 자동화에서 결과만 남으면 다음 질문에 답하기 어렵습니다.

```text
이 값은 어디서 왔는가?
어떤 단계가 이 값을 읽었는가?
어떤 단계가 이 값을 바꿨는가?
외부 API 결과가 어떤 객체에 반영되었는가?
실패했을 때 어디까지 진행되었는가?
```

OntoFlow는 이 질문에 답할 수 있는 기록 구조를 목표로 합니다.

## 2. 실행 중 상태

실행 중 상태는 워크플로우 단계 사이에서 공유되는 값입니다.

예를 들어 병원 예약 흐름에서는 다음 값이 실행 중 상태가 될 수 있습니다.

```text
환자 식별자
희망 진료과
의사 후보
가능 시간대
선택된 시간
예약 후보 번호
외부 API 응답
실패 사유
```

## 3. 실제 데이터 변경 이력

실제 업무 객체가 바뀌면 변경 이력을 남깁니다.

```text
어떤 객체가 바뀌었는가
어떤 속성이 바뀌었는가
이전 값은 무엇인가
새 값은 무엇인가
어떤 워크플로우 실행에서 바뀌었는가
어떤 외부 호출 결과 때문인가
누가 확인했는가
```

## 4. UI/UX 관점

사용자는 다음 화면을 기대할 수 있습니다.

| 화면 | 설명 |
|---|---|
| Workflow Run Timeline | 단계별 실행 결과를 시간순으로 봅니다. |
| Object State Timeline | 특정 업무 객체의 상태 변경을 봅니다. |
| Data Flow View | 어떤 값이 어느 단계에서 어디로 이동했는지 봅니다. |
| Validation View | 어떤 값이 검증을 통과하거나 실패했는지 봅니다. |

이 화면들은 단순한 로그가 아니라 업무를 이해하기 위한 추적 도구입니다.
