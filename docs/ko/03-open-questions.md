# 공개 질문

외부 리뷰가 특히 필요한 질문을 모읍니다.

## 1. 상태 전달

워크플로우 값은 노드 간 데이터 선으로 전달해야 할까요, 아니면 이름 있는 상태 슬롯으로 관리해야 할까요?

OntoFlow는 현재 제어 선만 두고, 값은 상태 슬롯으로 읽고 쓰는 방식을 선호합니다.

## 2. 온톨로지 개입 범위

온톨로지 정본은 워크플로우 실행 중 어디까지 개입해야 할까요?

현재 입장은 다음입니다.

- 객체 역할과 슬롯 타입을 정의한다.
- 값을 검증한다.
- 영속 쓰기를 제약한다.
- 판단 근거를 설명할 수 있게 한다.

## 3. 대화식 입력

자연어 입력은 워크플로우 엔진의 일부여야 할까요, 앞단 컴포넌트여야 할까요?

OntoFlow는 대화식 입력을 앞단 컴포넌트로 봅니다. 대화는 워크플로우 실행과 슬롯값을 제안하지만, 실행의 주체는 Workflow Manager입니다.

## 4. Gate 경계

승인 절차는 코어 기능이어야 할까요, 확장 컴포넌트여야 할까요?

OntoFlow는 Gate를 확장 컴포넌트로 봅니다. 코어는 일괄 등록과 직접 편집만으로도 동작해야 합니다.

## 5. 용어

외부 문서에서는 어떤 용어가 가장 명확할까요?

- TBox / ABox
- Type Layer / Instance Layer
- Persistent Knowledge
- Object Instance

용어에 대한 의견을 환영합니다.
