# Workflow Manager

Workflow Manager는 업무 절차를 실행하고, 각 단계가 어떤 값을 읽고 썼는지 기록하는 컴포넌트입니다.

## 1. 목표

```text
단계별 실행 순서를 명확히 한다.
외부 API와 MCP 도구 호출 입력값을 명시한다.
호출 결과를 업무 객체와 연결한다.
실행 중 상태값 변화를 추적한다.
실패, 재시도, 보류 상태를 구분한다.
```

## 2. 기본 단위

| 단위 | 설명 |
|---|---|
| Workflow Definition | 업무 절차의 설계도입니다. |
| Workflow Run | 실제 한 번 실행된 업무 흐름입니다. |
| Step | 조회, 판단, 호출, 반영 같은 실행 단계입니다. |
| StateSlot | 단계 사이에서 공유되는 실행 중 값입니다. |
| Action | REST API, MCP 도구, 내부 서비스 호출입니다. |
| Action Result | 호출 결과와 후속 매핑 대상입니다. |

## 3. 외부 API 연동

외부 API를 호출할 때는 다음을 분명히 해야 합니다.

```text
어떤 업무 객체의 값을 입력으로 썼는가
어떤 파라미터 이름으로 전달했는가
응답의 어떤 필드를 받았는가
그 결과를 어떤 업무 객체에 연결했는가
실패하면 어떤 상태로 남겼는가
```

이 기준이 있어야 병원 예약, 설비 점검, 조치 생성 같은 흐름을 사후에 다시 추적할 수 있습니다.

## 4. 버튼식 실행과 대화식 입력

초기 구현은 버튼식 업무 자동화를 우선합니다.

대화식 입력은 사용자의 자연어 요청을 워크플로우 입력값으로 바꾸는 앞단 모듈로 봅니다. 핵심 Workflow Manager는 대화 입력이 있든 없든 같은 실행 구조를 사용해야 합니다.
